## 2. What the capture is

`build_static_crtc_cpr()` emits a real 16 KiB `cb00` cartridge (R0=63, R1=40,
R4=38, R6=25, R9=7, then HALT). Boot goes through the production path — T80
surrogate, CPR parser/service, Plus MMU, motherboard, SDRAM client — before
the frame taps are sampled. After CPR apply, two warmup frames are discarded
and N requested frames are delimited by `selected_vsync` 0→1 edges, each
sampled per 64 MHz tick. Two consecutive steady-state frames must agree on
sample count, raw/selected edge counts, DE/hblank/vblank ticks, and the
FNV-1a64 over the serialized sample fields; the hash must be nonzero and the
two frames identical. That is a self-equality proof of a stable raster, not a
correctness proof against hardware.

## 3. CPU honesty: reduced TV80, fixture-proven opcodes only

The fixture CPU is the reduced TV80 (`sim/plus/tv80/`), not the production
VHDL T80/T80pa, and `JR JumpE` is unused with `JP cc` effectively
unconditional in this configuration. The static program therefore uses only
opcodes proven by `test_p10a_deterministic_boot` on this surrogate:
`LD BC,nn`, `LD A,n`, `OUT (C),A`, unconditional `JP` (`0xC3`), `HALT`. It
contains no `JR`/`DJNZ`/`LDIR`/`JP cc`/interrupts/FDC/ASIC-unlock. Any
branch-dependent or conditional software claim is out of scope, and the output
header records
`cpu_surrogate=t80pa_wrapped_reduced_tv80` permanently. The `programmed` gate
(CRTC R9 write observed) plus two post-program frame delimiters puts capture
on a steady-state boundary without pinning RTL output values.

## 4. Synthetic-only evidence; no oracle claims

Hashes prove only self-equality of two consecutive steady-state synthetic
frames. There is no arbitrary-title/demo CPR oracle, no hardware comparison,
no screenshot reference, no golden hash committed, and no RGB diffing.
Malformed (`bad magic`) and truncated CPRs are rejected before boot
(`test_b3_malformed_cpr_rejected`, `test_b3_truncated_cpr_rejected`), and an
independent re-run must serialize bit-identically
(`test_b3_repeat_capture_stable`). At most 16 frames with 2 warmup frames;
the header records the 64 MHz fixture divider (`production_clocking=0`) so a
fixture-vs-production clocking confusion is impossible.

## 5. Raw vs selected taps; shared filter-dependent payload

`raw_hsync/vsync/de` are the motherboard `hs_sel/vs_sel/de_sel` source taps
(pre-filter truth); `selected_hsync/vsync/hblank/vblank` are the production
output tuple after `SYNC_FILTER`. `rgb/ma/ra/vram_addr/word/byte` are shared,
filter-dependent taps (`crtc_shift` shapes `vram_d` before both points; the
header states this; no pre/post-filter payload pair exists). Timing-shape
equality may cite raw-vs-selected edge counts; any brightness/color/geometry
claim is filter-contaminated and is not a CRTC oracle. Off (2) is the default
per B7; Full (0)/Live (1) only as explicit parameter overrides, never changed
by this slice.

## 6. CLI, serialization, gates

- `p10_boot_tests --capture-cpr <path> --frames <1..16> --output <fresh-path>
  [--build-id <text>]`; `--help` alone. Default (no args) runs the P10 suite
  including the five B3 tests.
- Output creation is atomic-exclusive: a pre-flight check refuses an output
  identical to the CPR input (canonical + device/inode equivalence, so a
  symlink to the input is caught) and any pre-existing path; the file is then
  created with `O_CREAT|O_EXCL|O_NOFOLLOW`, so a file appearing mid-run
  (EEXIST) and any symlink at the path — including a dangling link the
  pre-check cannot see — are refused instead of followed (the open reports
  ELOOP where O_NOFOLLOW reports the refused follow, EEXIST where the link
  entry itself collides with O_CREAT|O_EXCL as on macOS; a `symlink_status`
  check names the symlink case on every platform). Every
  timeout/abort/shape/provenance/I/O violation throws a named `TestFailure`;
  capture never emits partial frames as success (exit nonzero; the caller
  must use a fresh path on retry since no partial file is unlinked).
- Provenance in every header: CPR size + FNV hash, Plus model + name,
  fixture/production clocking flag, simulator identity (binary path+size+fnv,
  or `user_build_id=`), filter selector, requested/warmup counts, budgets.
- `test_b3_capture_cli_validation` pins the fail-closed contract without
  simulation: bad frame counts (0/17/non-numeric), missing trio member,
  duplicate flags, `--help` combined, unknown arg, same input/output path,
  pre-existing output, symlink-to-existing output (pre-check), dangling
  symlink (exclusive-open primitive, ELOOP/EEXIST by platform). Probes are cwd-local and removed
  afterwards; no OS temp directory dependency.
- Real-CLI evidence for this session is listed in section 8; session logs
  live in `.coord-inputs/` (untracked), never in `/tmp`.

## 7. P10j disposition: source-verified chain, ready for reviewer to clear

The `plus_sprite_ram` same-port read-during-write divergence (behavioral
old-data vs M10K port-A NEW_DATA_NO_NBE_READ) is unreachable, verified end to
end against production sources (not inferred):

1. `plus_sna_parser.v`: `busy = sna_download || cpc_plus_byte_wr ||
   !fifo_empty || asic_sna_wr` — high while any SNA write is still in flight,
   including the post-download FIFO tail.
2. `Amstrad.sv:636`: `sna_finish_pending` clears (starting `sna_apply_cnt=5`)
   only when `!plus_sna_busy` — every `asic_sna_wr` has retired first.
3. `Amstrad.sv:726-727`: `reset_base` holds top-level `reset` through
   `sna_download | sna_finish_pending | (sna_apply_cnt > 2)`; `sna_load`
   fires at count 1, after release but with no SNA write in flight.
4. `rtl/T80/T80pa.vhd:148-152`: while `RESET_n` is low the production CPU
   forces `RD_n/WR_n/MREQ_n` high, so `mem_rd = ~(RD_n | MREQ_n)` in
   `Amstrad_motherboard.v:146` is low, so `spr_host_rd` in
   `asic_regs.v:573` is low — no port-A CPU read can coincide with an SNA
   write. A Z80 bus cycle also never asserts RD and WR together, closing the
   CPU-write/CPU-read same-cycle case.
5. The write path deliberately lives in the other reset domain:
   `asic_regs.reset` is `plus_asic_reset`, NOT held during the drain, so
   `spr_host_wr`/`sar*_wr` still land; the invariant is carried by the
   top-level-reset → CPU-bus-idle chain, and the comments now say so.
6. The video port is read-only; mixed-port SNA-write/video-read is OLD_DATA
   on both model and silicon. Mapping authority: Quartus run `33392854459`.

Residual is model-inference, not debt: the P10 fixture exercises the reduced
TV80 rather than T80pa and never drives the SNA path, so the chain above is
source proof, not simulation proof. P10j (docs/plus/plus-review-2026-09-03.md
section 4, OPEN LOW) is recommended for reviewer clearance on the strength of
the two comment-only notes plus this derivation; no RTL edit was made or is
proposed.

# B16: load-time Plus model selection

A valid CPR loaded with Plus model Off selects 6128+. Failed or aborted loads
preserve the existing model. A CPR loaded with GX4000,
6128+ or 464+ selected preserves that model. An SNA v3 header type 4, 5 or 6
selects 6128+, 464+ or GX4000 respectively. Classic and unknown headers preserve
the current Plus choice; changing that policy is separate work.

## Integration contract

`rtl/plus/plus_load_model.v` owns model selection and the shared F1/status
publisher. `Amstrad.sv` feeds its effective model to the existing Plus decoder
and consumers. The SNA CPU/header decoder, chunk parser, `plus_sna_apply`
interface and classic RAM-map handling are unchanged.

The CPR selection is sampled on `cpr_finish_pending && !cart_service_busy`,
the same edge that starts the seven-cycle apply countdown, and is gated by
`cart_image_valid`. The memory service finalizes validity before it drops busy. The SNA selection
is sampled at apply count 5, while owner reset is still held; owner reset
releases at count 2, the registered top reset follows, and CPU state is applied
at count 1 with `sna_hold` still active. A restarted SNA download clears the
helper's saved header and suppresses preparation from an abandoned countdown.
The header policy comes from offset 6D in
[the SNA format](../specs/formats/Snapshot%20%28.SNA%29%20file%20format.md).
Reserved type values in pre-v3 headers do not select Plus.

`sys/hps_io.sv` captures `status_in` into `status_req` on a rising `status_set`;
it does not synchronously copy that request into `status`. Consequently the
helper retains the selected model locally until Main echoes it. The OSD
publication uses the same model bits. Requests are serialized until Main echoes the outstanding model/tape-sound
fields, with a low cycle for the HPS edge detector. New load selections still
take effect locally immediately; their publication waits for the earlier echo.
This prevents an older echo from overriding a newer selection even when the
newest choice equals the original status. Pending F1 tape-sound toggles survive
coalesced publications. Reset/apply (0), detach (32) and snapshot-save (38)
action bits are cleared in publications; other settings come from live status. Main persists settings only
when the user saves them.

## Evidence and limits

- Focused test: `make -C sim/plus b16-load-model`. With the previous direct
  status behavior at the new helper boundary it failed with
  `FAIL B16: CPR Off must select 6128+ without waiting for Main` before the
  timing implementation. The implemented helper passes.
- The fixture executes the production `plus_sna_apply` controller and checks
  selection before owner reset releases and at CPU apply. It covers all four
  initial model settings against headers 0–7, stalled drain, delayed Main echo,
  manual model changes after echo, an aborted restore, pre-v3 headers, invalid
  CPR rejection, valid CPR preservation, unrelated settings, action-bit
  clearing, held F1 overlap, two F1 presses before echo and two SNA restores
  returning to the original model before the first echo. The last case first
  failed with `older echo must not override a newer SNA selection`; the
  invalid-image and action-bit cases also failed before their fixes.
- CPR drain/countdown wiring is checked against the production top-level
  source; the focused fixture drives its completion event directly. It does
  not execute the top-level cartridge parser or SDRAM transaction.
- Fresh cross-provider review: Claude Opus 5 run
  `20260922T000746Z-53847-b9a1` identified the invalid-image guard and action-bit
  concern. Follow-up `20260922T001601Z-65220-f2d2` approved the final delta with
  no blockers, including the parent-found stale-echo repair. Reviewers ran no
  suites. The parent owns final gate acceptance below.

The publisher relies on Main eventually echoing a status request. If an echo
never arrives, the local model remains selected and later publications wait;
manual OSD model changes cannot retire that override until the echo arrives
or the core reloads. There is no timeout that could reintroduce the stale-echo
race. Validate normal Main/OSD round trips during hardware acceptance.

This is source/simulation evidence. No synthesis or device test was performed
on this branch. On hardware, confirm CPR-from-Off boot and OSD update, preserved
Plus selections, and SNA types 4/5/6 restoring with matching OSD models and no
manual reload. A cartridge snapshot still requires its cartridge ROM loaded.
Classic-header-to-Off policy remains deliberately unresolved. B18 owns classic
capture/header/round-trip acceptance; this work does not close that gate.

## Device finding (2026-09-22)

On RBF `cdcb3c3` the CPR-from-Off path never ran: `CONF_STR` disabled the CPR entry
(`d2F8`, mask bit 2 = `plus_mode`) with Plus Off, and Main stops an MGL at a disabled
item. The entry is now ungated (`F8,CPR,...`), pinned by `sdram_cartridge_tests`.
RBF `4027f5e` with the ungated entry boots Sonic from Plus Off on device, and a
header-4 SNA selects 6128+ on `cdcb3c3`. OSD echo and SNA types 5/6 are unobserved.
Details: [device record](../investigations/hardware-runs/device-acceptance-cdcb3c3-2026-09-22.md).
A bounded same-day check on exact `cb60ff8` also boots the unchanged Eerie CPR
from saved Plus Off and shows coloured scene progression without manual model
selection ([record](../investigations/hardware-runs/b16-cb60ff8-device-2026-09-23.md)).
This confirms automatic Plus activation, not independent live-OSD/model readback;
the remaining OSD and SNA cases above stay open.

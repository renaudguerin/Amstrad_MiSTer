# B20-4: PRI phase across HSYNC widths

**Evidence slice, 2026-09-23; no RTL change.** At source base
`b5bf5965470b85365d26158d44424439fc116b1e`, the connected Plus video/timing
modules produce width-dependent PRI timing, capped at six character cycles.
This agrees with revised Arnold §2.4 for ordinary widths and contradicts the
fixed ten-microsecond account. It does **not** adjudicate which account describes
original ASIC hardware. Preserve the accepted nine-bit PRI no-wrap policy.

## Fresh source reading

- [Revised Arnold §2.4, archived 2025-01-02](https://web.archive.org/web/20250102091704/https://www.cpcwiki.eu/index.php/Arnold_V_Specs_Revised),
  CPCWiki revision **115989**, last modified 2024-05-13 17:59, was retrieved and
  read afresh. The live page returned a Cloudflare challenge. The revised text
  locates PRI at monitor-HSYNC trailing edge, makes its position depend on R2
  and R3, and gives width 14 firing at cycle 6. Its sentence about values ≥6
  says “position”; the surrounding width discussion and explicit width-14
  example establish the intended width clamp. It separately describes possible
  double firing when HSYNC crosses a scanline boundary, and excludes vertical
  adjustment. The comparison explicitly includes a zero ninth PRI bit.
- [Original Arnold issue 1.5 §2.4](../../specs/plus/_Arnold%20V_%20Specification%20-%20Issue%201.5%20-%2010th%20April%201990.md)
  says the programmed interrupt occurs at the end of the specified scanline;
  it does not provide the phase discriminator.
- [Thacker, Extra CPC Plus Hardware Information, Raster Interrupts](../../specs/plus/Extra%20CPC%20Plus%20Hardware%20Information.md)
  explicitly claims independence from width and ten microseconds after HSYNC
  starts. The later discussion of DMA/interrupt timing also leaves a
  ten-cycle observation marked for checking. These are source claims, not a
  fresh measurement with a specified signal tap or CPU-latency subtraction.
- [Further details of timing](../../specs/plus/Furthur%20details%20of%20timing.md)
  describes the monitor shaping as starting two microseconds after CRTC HSYNC
  and ending at raw HSYNC end or six characters after start, whichever is
  earlier. It says widths 1–2 produce no monitor pulse. This corroborates the
  shaping model, but does not independently establish PRI behavior for those
  widths. Its interrupt discussion concerns the compatible 52-line mechanism.

The [earlier source comparison](scrapes-interrupt-findings-2026-09-22.md) correctly
kept the phase conflict open; revised Arnold is now freshly verified rather
than known only through the digest. No source here displaces the Copter-backed
no-wrap decision.

## Clock-level observation

A one-shot probe adapts `sim/plus/p1_video_test_top.v` and the `Bench` driver in
`p1_pixel_phase_test.cpp`. The **unmodified** `asic_ga_timing` supplies
`CCLK_EN_N` to the **unmodified** `asic_video`; raw HSYNC/VSYNC return to timing.
The added connections are PRI=55, `{LINE[5:0],ROW[2:0]}` to `crtc_line`, ADJ to
`crtc_adj`, and observation ports for shaped HSYNC and `INT_N`. This matches the
production comparison/cadence wiring in `Amstrad_motherboard.v`; it does not
elaborate the complete motherboard, CPU, ASIC register bus, or monitor filter.

Setup: 64 MHz master clock (one tick = 15.625 ns), `cen_16` every fourth tick,
`fast=0`; R0=63, R1=40, R2=46, R3=`0x80|width`, R4=38, R5=0, R6=25, R7=30,
R8=0, R9=7, R12=R13=0. Each width 0–15 uses a fresh model, reset/programming,
two-line settling, then a 312-line observation. R2=46 keeps even the width-0
(16-character) pulse inside the line. Thus this experiment does not test the
revised source's cross-line scenario.

A direct `intack` input clears simulation's initial IRQ level and acknowledges
an observed IRQ on the following clock. It deliberately isolates request timing
from CPU response; the resulting one-clock IRQ duration is **bench stimulus**,
not a claim about CPU acknowledge latency. Other bus inputs remain idle.
Samples are taken after each master-clock rising edge and combinational settling.

All offsets below are **master-clock ticks after raw HSYNC rises** on matching
line 55, where VC=6, RC=7 and raw start HCC=46. Divide by 64 for microseconds.

For example, width 14 produced raw rise at tick 228233, shaped rise at 228361,
shaped fall at 228617 and IRQ assertion at 228618. HCC was 52 at assertion;
VC/RC stayed 6/7 throughout. The one-tick delay follows the registered
`hsync_o_q` edge detector and clocked `INT_N` assignment. It is not evidence for
an original-ASIC sub-character latency requirement.

At line 311 (VC=38, RC=7), the same width-dependent raw/shaped edges occurred,
but no IRQ asserted for any width. This is a negative observation consistent
with the unchanged nine-bit comparison, not a new hardware no-wrap proof.

## Reproduction and acceptance boundary

The temporary probe is intentionally not a permanent regression test: it records
what RTL does without declaring either disputed source correct. Files used for
the run are retained in this checkout's ignored
`sim/plus/obj_dir/b20-pri-phase/` (`generate.py`, `top.v`, `probe.cpp`,
`events.csv`, `build.log`), with runnable originals under `/tmp/b20-pri-probe/`.
They are local handoff artifacts, not files delivered by this documentation
commit. From this source base, the retained generator and command reproduce the
observation:

```sh
mkdir -p /tmp/b20-pri-probe
python3 sim/plus/obj_dir/b20-pri-phase/generate.py
make -C sim/plus /tmp/b20-pri-probe/obj/probe \
  P1VID_TOP_SRC=/tmp/b20-pri-probe/top.v \
  P1VID_TEST_SRC=/tmp/b20-pri-probe/probe.cpp \
  P1VID_OBJ_DIR=/tmp/b20-pri-probe/obj \
  P1VID_TEST_BIN=/tmp/b20-pri-probe/obj/probe
/tmp/b20-pri-probe/obj/probe > /tmp/b20-pri-probe/events.csv
```

Build/run completed with Verilator 5.052. This was an observation, not a
fail-before/pass-after behavior test. No production/testbench/build source is
changed in the commit, so the selected simulation gate and independent code
review are not applicable to this documentation-only slice. No synthesis,
MiSTer access, or original CPC Plus measurement was performed.

**Disposition:** retain the existing phase rule for now. Its ordinary-width
behavior agrees with revised Arnold at character resolution; it conflicts with
Thacker's fixed +10 µs claim. The experiment cannot resolve that authority
conflict by measuring the implementation that already chose one side.

**Residuals:** original-hardware timing against a named HSYNC tap; widths 1–2
PRI semantics; cross-line HSYNC/raster-match transitions and possible double
firing; exact sub-character phase; and CPU acknowledgement/IRQ overlap remain
open. The width sweep is not an Eerie Forest or other title acceptance result.
Any shared interrupt RTL change must first be coordinated with the Eerie owner
and coordinator, with a source/hardware-derived failing vector before editing.

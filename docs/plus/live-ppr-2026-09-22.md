# B20-1 live PPR writes — implementation report (2026-09-22)

Plus stream only. No ack/vector change, no Sonic claim, no hardware or
synthesis claim. Validation is limited to the selected Verilator benches.

## Source and diagram adjudication

- S02 p.4 (*ASIC et DMA son*): a changed pause unit takes effect
  immediately; the worked example (unit 5, counter at 3) wraps at once and
  the next value is 0.
- S22 p.10 (*Prenez la pause*): a mid-PAUSE PPR change — even same-value or
  larger — advances the PAUSE to its next iteration; a change on the last
  line of an iteration is seamless.
- S22 p.10 diagram (visually checked from the original PDF): initial PPR3 PAUSE5,
  write during iteration 2 at up-counter 2; the next line is iteration 3 /
  up-counter 0 for **both** new PPR1 and new PPR6. This settles the
  reset-vs-restart ambiguity: truncate
  the current iteration; the next HSYNC completes one pause tick and
  reloads the new PPR. Same-value effect is explicit in the S22 prose;
  the final line of an iteration is invisible.
- S02 p.4 agrees the next value is zero. Resetting the down-counter to
  the new PPR would restart the same interval and contradict S22.

Source IDs and exact local PDF filenames are in the
[source inventory](../reference-ingestion/scrapes-2026-09-22.md).
Page numbers here are one-based PDF pages.

Exact same-64 MHz write/HSYNC phase is a deterministic model convention,
not a measured silicon fact (see Limits).

## Implementation

- `rtl/plus/asic_regs.v`: per-channel registered one-shot `ppr0_wr..2_wr`.
  CPU decode `asic_cs && mem_wr` on the PPR address only, `sna_wr`
  excluded. Rising edge only, so a stretched bus level yields one pulse.
  The pulse is registered, therefore the `ppr[]` byte written on the
  decode edge is already settled when the pulse is live for the DMA.
- `rtl/plus/asic_dma.v`: while `pause_cnt>0` a write forces
  `prescaler_cnt` to 0, so the next HSYNC ticks once (`pause--`) and
  reloads the new PPR. HSYNC edge handles
  `prescaler==0 || ppr_wr` as one tick with new-PPR reload (no double
  event, reload wins); outside HSYNC the pulse zeroes only an actively
  pausing channel (`dcsr_ena && pause_cnt>0`). `active_ch` still uses the
  old pause count: the existing d03 cadence is unchanged.
  Reset/`sna_load` priority is absolute (earlier branches). No effect
  while `pause_cnt==0`.
- Wiring: `rtl/Amstrad_motherboard.v` and `sim/plus/plus_p8_test_top.v`
  carry the three events production-style. `p10_dma_ppi_test_top.v`
  ties them to 0 (no register file in that seam);
  `asic_dma_test.cpp` ties them to 0 (setup writes occur while idle).
  `p4_sprites_regs_test_top.v` leaves the new regs outputs explicitly
  open.
- Disabled suspended channel (`pause>0` but `ena==0`) keeps its
  prescaler: writes are ignored until re-enable. Documented model choice;
  sources assume an enabled pause. No broad redesign.

## Limits (not hardware)

- A registered PPR event consumed on the HSYNC edge produces a single
  tick with new-PPR reload. A CPU decode first seen on that same edge
  produces its registered event on the following clock. This is the declared 64 MHz model priority
  for the bench; it cannot claim physical ASIC phase.
- Early vs late mid-line agreement pins the HSYNC-granularity contract
  (one effect per inter-edge write), not sub-microsecond timing.
- Disabled-suspend preservation is a model choice; the sources describe
  an executing PAUSE. Same-value actuation is explicitly documented by S22.
  SNA event exclusion preserves the existing snapshot restore contract.
- No device capture, no AmSpirit comparison, no Quartus/synthesis run
  for this change. Stream branches stay Tier A unless explicitly
  requested.

## FlowLIB warning: established trigger

Unchanged-cartridge production-T80 replay enters the machine check at&37B7.
The first stage executes repeated LD(DE),A at&9000 (A13=0), expecting a
non-raster IM2 vector. The core takes82 raster handlers and no alternate
handler; BF01 remains0. At&37ED it returns A=1, and caller&0119 paints the
warning. AmSpirit's1s snapshot contains the third-stage HALT routine at&9000,
showing that it passed the first-stage check.

The source of the deliberate hardware bug is external Plus bus logic:

```
ASIC_IORQ_n = CPU_IORQ_n | (~physical_READY & ~A13) | reset
```

The [CPU schematic](https://oldwiki.cpcwiki.eu/imgs/8/84/CPC_Plus_CPU_Schematic.jpg)
connects IC116G3 to CPU /WAIT (the raw ASIC READY net) and A13. The diode/reset
network and NOR stages yield the equation above. The
[original circuit discussion](https://oldwiki.cpcwiki.eu/forum/amstrad-cpc-hardware/amstrad-plus-and-im2-bug/100/)
and [measured trace discussion](https://oldwiki.cpcwiki.eu/forum/amstrad-cpc-hardware/amstrad-plus-and-im2-bug/150/)
confirm the mechanism; the [logic-analyser image](https://oldwiki.cpcwiki.eu/imgs/7/7e/IM2_Plus_Ack_Bug.png)
shows one CPU acknowledge becoming two ASIC-side pulses, vector06 then04.

Use raw Plus READY, not synthetic cartridge/DMA stalls or the T80 idle-WAIT
workaround. The circuit also affects ordinary I/O. Instruction sensitivity
must emerge from bus phase; an A13-only vector override is not this mechanism.
The original machine check's second-stage RET NZ does not set flags from its
newly loaded marker, so a regression test must use an explicit flag-setting
check rather than copying that weakness.

Private `flowlib/README.md` records disassembly, original source captures,
complete replay commands and the implementation handoff.

## Cross-line raster interrupt: second finding

[Revised Arnold §2.4](https://web.archive.org/web/20250102091704/https://www.cpcwiki.eu/index.php/Arnold_V_Specs_Revised)
describes an additional interrupt at entry to a matching scanline when raw
HSYNC overlaps that boundary. The existing implementation only handles the
ordinary monitor-HSYNC trailing edge. A connected production GA/video probe
with R0=63, R2=51 and HSYNC width14 fails: it produces the ordinary event but
omits the line-entry event. R2=49 is a noncrossing control and retains exactly
the ordinary event. A candidate supplying the missing event passes both.

Settled snapshot A/B replays reproduce the corrupted Buddha background and
fragmented sphere with baseline RTL, and coherent images with the candidate.
The Buddha SPLT1 write moves from line2 to line1, before the existing split
capture. No screen-split comparator change is needed. Snapshot convergence
is supporting diagnostic evidence: omitted transient state and an explicitly
reconstructed RMR2 prevent treating it as an exact normal-boot timeline.

The sphere uses R2=50, where raw HSYNC falls on the line boundary. Using the
previous raw-HSYNC sample repairs this scene, but that simultaneous-edge
ordering remains an inference requiring hardware adjudication. The source
clearly establishes the R2=51 overlap case, not the exact R2=50 seam.
Focused commands, before/after logs and replay limits are in the private
`late/PRI_FINDING.md`. Production implementation passes the connected regression, reset/import/live-write
guards and eight GA differential tests. The existing synthetic PRI fixture had
reversed HSYNC polarity; corrected active-high stimulus with a full monitor
shaper window passes its unchanged assertions on both old and new RTL.
The two-fix hardware evidence below confirms coherent Buddha and sphere scenes;
the simultaneous-edge hardware rule itself remains provisional.

## Late freeze: DMA operation-bit decoder

[Kevin Thacker's original-hardware notes, DMA opcode table](https://cpctech.cpcwiki.de/docs/cpcplus.html)
define the upper nibble as independent control/REPEAT/PAUSE bits, with bit15
unused; LOAD applies only when the three operation bits are zero.
[Quasar, L'ASIC, “1 + 1 = ?”](http://quasar.cpcscene.net/doku.php?id=assem:asic)
confirms ignored bit15 and describes combined operations. STOP suppresses
LOOP; REPEAT|STOP still installs its loop context. Quasar explicitly did not test
whether INT suppresses LOOP, so that priority and the existing ordinary REPEAT0
convention remain unchanged.

Opus review exposed a count conflict in the proposed REPEAT|LOOP extension:
Quasar's two-high/three-low-beep example disagrees with an undecremented new
count under the retained Arnold N+1 ordinary-loop convention. That unsupported
extension is excluded: combined REPEAT|LOOP without STOP retains its previous
unimplemented/no-op behavior, not a claim that hardware ignores it. The demo's
F0C0 and5020 have no LOOP bit and do not depend on resolving this conflict.
The pause/stop/re-enable control pins the existing preserved-suspend model;
it is not an independently measured hardware rule.

The core instead decoded the entire high nibble as mutually exclusive cases0–4,
silently skipping5–F. The175s production replay reaches sample-tail words F0C0
at3104 and5020 at3106, skips both, then executes4010 at3120 and enters the
manual-ack interrupt storm described below. Correct bit decoding applies the
combined pause/repeat and pause/stop, ending at SAR3108 without reaching that
interrupt. This is a general instruction-decoder defect, not a title-specific
STOP or interrupt-acknowledgement workaround. We do not assume that reaching
graphics memory is intentional; the reference tolerates that tail using the
hardware command rules.

The initial diagnostics fail before repair across all three channels, including
bit15 aliases and the actual sample tail. Review removes the unsupported
combined-loop expectation; independent STOP/context and alias controls remain. The connected production DMA/register test additionally
proves DCSR enable clearing and absence of the unwanted IRQ, then deliberately
raises a DMA IRQ to verify manual-ack retention and CPU clearing. A five-second
175s title replay changing only the DMA decoder passes250 frames: DMA0 stops
at SAR3108 without IRQ and rendering continues with12675 split writes/second.
That replay predates exclusion of the unused combined-loop extension; the
F0C0/5020 paths it exercises remain unchanged. Private
`late/DMA_DECODE_FINDING.md` preserves primary-source captures, exact commands,
baseline logs and snapshot limitations. No full normal-boot hardware freeze
acceptance is claimed for this fifth candidate yet.

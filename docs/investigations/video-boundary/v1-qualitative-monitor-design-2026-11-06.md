# V1 digital monitor response

Astra-medium design, revised after Opus 5.5/high review on 6 November. The
rise-owned deadline, asymmetric pull, moving-raster coordinates and fixed-width
reference below address the four required findings. This is GO for a bounded
offline prototype, not RTL or public-mode approval.

**Add CRT response as a fourth presentation choice. Keep Full as the default.** A physical CRT provides its own deflection. A scaler needs regular acquisition timing, but can display the *result* of horizontal deflection if the core moves the picture within that timing. One selector labelled **Video output**, with **Full / Raw pixels / Raw CRT / CRT response**, expresses both uses without combinations of switches. Use existing values 0–2 and allocate 3 only when the digital candidate passes. Value 3 currently falls back to Full, so an old configuration containing that reserved value would select the new profile. All connectors receive the selected presentation. Simultaneous raw analog and modelled HDMI would require a separate framework change.

## Where to connect it

The motherboard sends selected **raw CRTC** pins `hs_sel/vs_sel` to `crt_filter`. Full and Raw pixels select its complete HS/VS/HBL/VBL tuple. Raw CRT selects GA-shaped H/V sync, CRTC HS as HBL, and GA VBL. The filter's live-blank comment misidentifies its HS input. Raw HS contributes to source blanking, while the rendered DAC pairs already carry horizontal force blank. Fix that comment when wiring the new profile. The core's mixer/crop and the MiSTer framework receive a single video stream. [Motherboard](../../../rtl/Amstrad_motherboard.v), [filter](../../../rtl/crt_filter.v), [output chain](../../../rtl/amstrad_video_output.sv), [framework](../../../sys/sys_top.v).

Give the new profile two independent inputs:

- **Monitor stimulus.** Read the already owner-selected `hsync_ga` and `vsync_ga` at the master clock. Outside GA VS the active composite tip (`~SYNC_N`) equals GA HS, by the XNOR in both shapers. Inhibit at GA VS, discard a straddling pulse and wait for HS low before rearming. This approximates the horizontal portion of monitor input using existing signals. The acquisition raster supplies the coordinate system. [Classic shaper](../../../rtl/GA40010/syncgen_sync.v), [Plus shaper](../../../rtl/plus/asic_ga_timing.v).
- **Picture and acquisition.** Enter through the Raw pixels byte/blank policy: native fetch order, post-compositor `selected_source_rgb` (12 bits including Plus sprites), aligned source vertical-blank tag, regularized acquisition tuple. Both Full's shifted VRAM assembly and its eight-native-dot RGB history must be bypassed. The new displacement owns ordinary width positioning in this profile. Check the ordinary 4/5 and 5/6 relationships separately against existing relative-position evidence. Full's absolute positioning is a compatibility baseline. Preserve the Raw CRT direct path, its native cadence and its downstream bypass. Leave CRTC counters, GA interrupts, CPU reads, memory arbitration and sprite production upstream of all monitor state.

## Small horizontal model

Use one signed fixed-point sweep offset in native mode-2 dots per line. Positive means the sweep begins later and a stationary source edge moves left. A stored fraction lets small pulls accumulate. Start with a first-order relaxation toward a line target; add an independent frequency/velocity state only if this version fails a relevant held-out case. Settling over several successive lines is what makes a straight source edge bend. The following choices specify a causal *candidate*.

1. Prime from consecutive ordinary lines with one consistent GA tip and stable acquisition periods. Learn the nominal rising-edge position relative to filtered HS, and keep the healthy period L. Freeze both through the effect. Fix the width reference at 256 master ticks, the ordinary pulse cap in the current shapers. Starting in a sustained narrower width must retain its width offset. Until primed, present native position.
2. The regularized raster moves. The current filter can step HS and HBL on a sustained R2 pair, and VS can reanchor them. At every filtered line start measure the actual period P. Before applying the new line's displacement, subtract P − L from the carried phase in the same units. This expresses the same absolute sweep time against the new raster origin; future phase errors are measured against that new origin. Apply this change of coordinates exactly once, including to a pending displacement if finalized in the previous coordinate system. Hold L through isolated steps. If the step exceeds the supported displacement, or the filter declares HS missing, invalidate the estimate, run at native position and re-prime from consecutive healthy lines. Expose the existing absence flag explicitly if needed. Log each correction. The paired-R2 logic in the current [filter](../../../rtl/crt_filter.v) operates despite its historical “PRIVATE” comment.
3. Define half-open pulse ownership windows centred on the nominal rising-edge prediction, spaced by L. A tip belongs to the window in which it **rises**. At the window end, wait for an already-open tip's fall and take its actual width before finalizing. The GA HS cap bounds the wait by 256 ticks. A new rise exactly at the deadline belongs to the new window. Capture the previous result independently of starting the new collector. On a normal 4096-tick period, the reported T/A late tip at +1856 runs through the +2048 boundary; dropping it would erase the very response under study. Verify that chronology from the trace at prototype startup.
4. Choose the closest qualified rising edge as primary (earlier wins a tie). Its signed phase error plus half its measured width difference from the reference gives the proposed midpoint target. Reject subthreshold glitches. For the other completed tips add signed, width-weighted pulls with saturation. Start with **stronger early than late pull**. Symmetric sign-only weights cancel the equal-width opposing secondary tips reported in corrected T/E. Choose gains on T/A and T/E, without copying emulator constants. A running sum and closest-tip record suffice if the winner's secondary contribution is removed at finalization; avoid order-dependent saturation inside the sum.
5. Relax the fractional state once per finalized window: `next = phase + gain × (target − phase)`, with a shift-friendly gain between zero and one and bounded output. Latch it for the first subsequent acquisition line whose start follows finalization; apply the coordinate correction above at that start. If there is no qualified tip, hold the *absolute* phase through the missed observation. Never revise an emitted dot. Reset, SNA load, committed mode change or owner change invalidate the estimate and pixel history.

This models horizontal translation. Vertical roll, interlace recovery from composite alone, long-term horizontal frequency error, within-line stretching and elaborate loss of lock can wait. If acquisition itself stops providing usable lines, the response mode inherits that failure. B22 acquisition repair has a different acceptance criterion. A first-order curve can also miss genuine overshoot; record that residual before deciding whether a second state earns its cost.

## Place pixels without changing acquisition geometry

For a bounded displacement, a dot history suffices. At the native 16 MHz enable write every dot, including borders and source blanking, into a circular RAM. Emit each regularized raster coordinate after a constant **D** dots. For output coordinate x read the source at x + round(phase). Relative to the current input write pointer the requested age is D − round(phase). Choose D greater than the maximum permitted displacement plus RAM latency/margin; dimension the RAM for the oldest possible age and budget the synchronous read cycle explicitly. This handles either direction without reading future samples, buffering a frame, or fitting a clock to the monitor model.

Use integer nearest-dot reads in the continuous dot stream. Ordinary lines have enough blank margin for modest offsets; an unusually short line may read a neighbouring time interval. Record such crossings and visible artifacts. Saturate displacement at the design bound instead of wrapping an address outside retained history. Keep a fill counter since the last clear. Mask output black whenever the requested age is unavailable, including at phase zero, until the new owner has written enough samples. A physical RAM clear and per-dot valid bits are unnecessary. Carry the raw vertical-blank tag in the RGB word and apply it after conversion. Keep native horizontal DAC near-black.

Delay HS/VS/HBL/VBL, `field` (interlace/observation) and `frame_field` (VGA_F1) by the same fixed presentation latency. Carry the line's offset to its delayed HS edge in blank; a pending register suffices only if a second edge cannot overwrite it during the delay. Run matched tuple/field delay continuously so entering or leaving mode 3 can require **both live and delayed filtered VBL**, plus the existing CPU-phase or reset policy. Keep the acquisition tuple running during clipping and priming. Give the candidate its own native-cadence flag for colour conversion and observation; reusing `raw_crt` would also bypass crop, DE and scandoubling. Disable adaptive pixel rate/HQ2x in the first slice and verify other processing before exposing the option.

For sizing only, a ±48-dot budget, D = 64 and a 128-entry history cover ages 16–112 before pipeline adjustments. RGB plus mask consume 1664 bits, plus tuple/field and offset delay. Expect a few kilobits of storage, counters and adders. Pipeline width scaling away from the pixel path and confirm actual M10K packing, critical path and read latency in Quartus. Choose the production bound from measured displacement and saturation; routine saturation on the target corpus calls for revisiting that bound. None of these example sizes or gains is a CTM measurement.

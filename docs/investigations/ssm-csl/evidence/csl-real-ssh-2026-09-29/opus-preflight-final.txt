### The other safeguards
- **Main commands blocked:** any `ssh` call whose remote command contains `/dev/MiSTer_cmd` raises before it runs (line 40). That covers both `load_core` and command writes. The runner stops at `write_cfg` in any case, before `check_rbf_directory`. Line 99 repeats the check against the command log.
- **Intercept rewrite:** the rewritten remote command reads `…; timeout -s KILL N sh -c '<cat> > cfg' && echo CSL_WRITE_ACK && timeout -s KILL 10 sleep 8`, with `exec` removed. The ACK prints only after the bounded write succeeds. Only the first write is intercepted, so the restore write runs unmodified.
- **Staging removed:** line 96 fails on any `remote_temp` entry that has an `error` and no `exit_code`. Line 98 then checks over a separate connection that each staging path no longer exists. The same staging path appears twice in `remote_temp` (the forced write and the restore). That is harmless because `rm -f` is idempotent.
- **Evidence saved first:** the `finally` block writes `evidence.json` (line 103) before any fallback read, and again at the end.
- **Fallback:** the restore write's exit code, a re-read that the CFG matches the original, and the `rm -f` exit code are all checked (lines 110-112). The `patch` context has already exited by then, so the fallback uses the real `subprocess.run`.

### Remaining limitations (not blocking)
- If the fallback's `read_cfg() == original` check fails, the emergency staging file stays on the device. `original.CFG` is still saved locally, so you can restore by hand.
- If the fallback itself raises, it hides the original exception from the `try` block. Python still prints it as the chained context, and `evidence.json` has already been written.
- These still apply from the first review:
  - The test covers losing the connection after a completed write, not a truncated one.
  - Patching `subprocess.run` affects the whole process.
  - Keep the MiSTer slot to yourself so nobody saves from the OSD during the run.
  - Pillow must be installed on the host.

# Sonic GX interrupt audit and next checkpoint

Scope: Plus-only audit from integrated `abe9fd3fc557a8752920eae6881cbfaeb645e448`.
No device or AmSpirit mutation was performed. PRI no-wrap and B19 raster retention
remain unchanged; the [source findings](../../plus/references/scrapes-interrupt-findings-2026-09-22.md)
and [Copter acceptance](../../defects/copter271/README.md#4-resolution) retain their authority.

## Decision

No Sonic IRQ RTL repair is justified by the evidence collected here. An empty
vector fallback, live PPR write semantics and simultaneous same-channel DMA
set/clear remain distinguishable questions, not demonstrated title causes.
Continue from a reproducible title/game checkpoint, then trace the first bad
line and its preceding interrupt/register activity. Do not implement the A13
silicon bug or change PRI range to explain a screenshot.

## Cartridge identity and instruction evidence

The examined private media is
`local/test_media/cartridges/Sonic the Hedgehog (UK) (64K) (2025) [Original].cpr`,
524,556 bytes, SHA-256
`4cb31c7f1769989a029fe1bd7ffb04670d5d24570dc56b0417fac662fed887ae`.
Offsets below are within the named 16 KiB CPR chunk, not the RIFF file.

- `cb00:0060`: `ED 5E 3E B8 ED 47` is `IM 2; LD A,&B8; LD I,A` in
  the straight-line boot path. This verifies the initial table page; it does
  not prove that every later scene keeps it.
- `cb03:37F4`: `XOR A`, followed by direct stores to `&6C02`, `&6C06`,
  `&6C0A`, `&6C0F`, `&6801`, and `&6805`, then `PRI=&FF`. This is a
  zero-prescaler/automatic-ack setup sequence. It does not establish a live
  mid-pause PPR update.
- `cb30:392A` and `cb18:277E` contain `XOR A; LD (&6805),A`; the latter
  follows `LD A,&B8; LD I,A`. Raw opcode matches elsewhere in graphics or
  compressed chunks are not evidence of an executed register write.

The bounded static scout additionally identified `IM 2; LD A,&9F; LD I,A`
at `cb18:24B0` and `cb18:259B`. Sonic does not have one immutable I-register
value. At `cb18:24F3`, code sets I=&B8 and copies eight bytes from CPU &DBC8
to &B800; at `cb18:277A` it sets I=&B8/IVR=0 and copies &DBB8 to &B800.
With cb18 mapped at &C000, the source tables decode as:

| CPR offset / CPU source | DMA2, offset 0 | DMA1, offset 2 | DMA0, offset 4 | PRI, offset 6 |
|---|---|---|---|---|
| cb18:1BC8 / &DBC8 | &833F | &8342 | &834A | &8352 |
| cb18:1BB8 / &DBB8 | &A29F | &A461 | &A4BC | &A500 |

These are static linked setup/table bytes, not an observed current table or
handler execution. The RAM handler bodies need a checkpoint dump with a
verified loading/relocation history. Likewise, `cb30:392A` is a chunk offset;
when page 30 is upper-mapped its CPU address is &F92A. It is not CPU &392A.
DCSR=0 disables channels but does not write ones to clear their pending flags.
No inspected static sequence proves a live PPR update, and indirect stores or
decompressed code have not been exhaustively excluded.

## Controller and CPU boundary

`asic_regs.v` samples `ack_src` at `intack && !intack_d`, in raster,
DMA2, DMA1, DMA0 order. The automatic DMA clear uses the same edge and pending
state; raster pending suppresses that clear. A continuous acknowledge cannot
reselect a source after its flag clears. IVR high bits remain live, but an
ordinary CPU cannot also perform a memory write during its acknowledge cycle.
Snapshot/reset overlap is a separate lifecycle question.

`asic_ga_timing.v` preserves PRI fire during `int_reset | intack` in
`raster_fire_pending`, then asserts the request after the window. The existing
`pr02`, `pr06` and `pr07` vectors respectively preserve no-wrap, acknowledge
provenance and retained raster fire. They were inspected, not rerun as an
unrelated baseline. The same-channel DMA set/clear expression remains
clear-dominant; its set-dominant comment is inaccurate. Changing the behavior
requires evidence of the collision and its hardware semantics.

The motherboard supplies the ASIC vector during Plus acknowledge and uses the
production `T80pa` CPU. `T80.vhd` takes the IM2 low address byte from `DInst`
at TState=2; `T80pa.vhd` connects that input directly to the bus and releases
IORQ on the same positive-enable edge. Thus the old asserted acknowledge and
held vector are still present when sampled. This is distinct from the later
`DI_Reg` latch used by other reads. The current path
has no A13-conditioned board-level doubled-ack mechanism. The interrupted
instruction, rather than handler/table placement, is the required discriminator.

The independent Opus architecture pass (`claude-opus-5`, high,
`20260922T025032Z-4393-ee3c`, clean exit) also found no justified pre-trace repair.
It highlighted the full DCSR write window, not just its first edge: a new INT
flag can be cleared on any clock while the write remains asserted, whereas a
STOP enable-clear pulse can be overwritten by the still-active CPU write on
a later clock. It also identified the unretained PRI=0 classic overflow during
DMA acknowledge. These are code observations with unresolved hardware policy.
Count their occurrence in the chosen trace; zero hits excludes them only for
that captured interval. The review's broader no-source-ack reachability
argument is not a substitute for observing the real instruction/board boundary.

## Harness correction and diagnostic limits

The old P10 fixture header says real T80, but its normal build substitutes
reduced TV80. It cannot validate general Sonic instruction/interrupt timing.
The opt-in D5 route translates production `rtl/T80/T80pa.vhd` with GHDL and
reuses the motherboard/cartridge/SDRAM fixture with production clocking and
WAIT enabled. Its adapter missed the newly connected HALT output: Verilator
failed with `PINNOTFOUND: halt_n`. Adding `HALT_n` to its existing port-case
mapping fixes this compile-time integration defect without changing RTL.

A scratch Sonic run used this production-T80 route and the unmodified CPR.
The first 128,000,000 master ticks (two emulated seconds) executed boot and
intro CRTC writes but no interrupt acknowledge. Initial R0–R9 writes were
`63,48,50,140,38,0,0,34,0,7`; the intro then changed R1/R2/R7 and R6.
Those observations demonstrate startup reachability only. In particular,
initial R6 is zero, not the later visible-height setting. They do not verify
Sonic gameplay, live PPR use, or correct IRQ phase.

The bounded extension reached stores from CPU &B843/&B846/&B849 to
PPR0/PPR1/PPR2, all zero, at ticks 287,310,083 / 287,310,339 / 287,310,595
relative to post-download execution. These were followed by DCSR=0, PRI=0,
SPLT=0 and SSCR=0. This establishes an executed initialization path, not the
live mid-pause PPR change described in source discrepancy I5.
The run stopped at its fixed 512,000,000-tick cap (eight emulated seconds),
reporting `RESULT acks=0 pc=b836`. It did not reach the active title/game IRQ
pipeline. No vector-selection or interrupt-collision result is claimed from
this run, and the cap was not extended further.

This fixture retains a behavioral external SDRAM model and a stubbed unused
classic GA, and starts from its own initial memory model. It is not a complete
hardware oracle or a device snapshot continuation. Scratch instrumentation is
not a supported capture interface.

Verification of the committed adapter correction:

- Fail-before: production-T80 fixture compile rejected `.halt_n(cpu_halt_n)`.
- `make -C sim/plus d5-boot-build`: passed after the correction.
- `sim/plus/obj_dir/d5_boot/d5_boot --controls`: passed model 1/2/3
  ROM0, ROM7 and all direct-page selections.
- `python3 sim/select_tests.py --run`: `select_tests: no simulation needed`.
  The opt-in D5 target is outside the selector index, so its explicit build and
  existing controls above are the relevant validation; the selector is not
  evidence that production T80 executed.

Fresh Opus code review (`claude-opus-5`, high,
`20260922T025938Z-24922-d5f9`, clean exit) approved the one-line adapter change
with no blocking findings and accepted these gates without rerunning them.
The optional suggestion to generalize output discovery was left out: this
bounded correction is sufficient and future missing ports fail at compilation.
Parent inspection also confirmed the generated `output HALT_n` declaration
and `.HALT_n(cpu_halt_n)` connection. Logs are retained locally under ignored
`docs/screenshots/sonic-irq-audit-2026-09-22/`.

   An additional matched intro checkpoint can localize whether corruption is

3. Record raw CRTC counters/HSYNC, PRI fire and pending retention, DMA request
   flags, `/M1`, `/IORQ`, `/WAIT`, sampled vector and interrupted instruction.
   Correlate these with `PRI`, `SPLT`, `SSA`, `SSCR`, `IVR`, DCSR and PPR writes.
   Derive the expected vector from pre-ack pending state, not the cleared flags.
4. For a bad split, compare the actual SSA/SPLT write completion to the actual
   line's R1 latch event and subsequent video fetch. Do not assume R1 remains
   48 or that SPLT=255 repeats on line311. Test PPR or empty-vector behavior
   only if the captured execution reaches that condition.

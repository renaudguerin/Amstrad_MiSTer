# B23: TV80 versus production T80 bus timing (2026-09-23)

## Disposition

The bench exposed a narrow fixture defect: TV80 held ordinary-fetch M1 low for
all four T-states, including refresh. `tv80_core.v` now releases it after T2,
matching the production `rtl/T80/T80.vhd` state machine. The reduced interrupt
acknowledge path is deliberately unchanged. The new M1 edge also changes refresh
masking in fixture consumers: `rtl/GA40010/casgen_sync.v` and the Plus GA use
M1 rising to set U708, affecting CAS and motherboard `vram_bs`. The source change
is narrow; its fixture impact includes video, so slow B6/B7 consumers are part
of acceptance. No production RTL or device work.

B23 is **partially addressed**, not full CPU equivalence. Memory, I/O and external
WAIT transfer pin parity now pass. Interrupt acknowledge timing, the absent
interrupt stack writes, and the production netlist's startup IORQ remain explicit
strict-parity failures. Use production T80 for interrupt-phase-sensitive evidence.

## Reproduce

Requires Verilator, GHDL and a C++17 compiler:

```sh
make -C sim/plus b23-cpu-diff
sim/plus/obj_dir/b23_cpu_diff/b23_cpu_diff_tests --strict
sim/plus/obj_dir/b23_cpu_diff/b23_cpu_diff_tests --trace > /tmp/b23-trace.log
```

The make target requires exact post-startup memory, I/O and WAIT pin parity and
non-vacuous completion/data checks. It prints IRQ differences as diagnostics;
its success is not full parity. `--strict` exits 1 on **any** sampled divergence,
including startup and IRQ. `--trace` logs every master clock; bus bit order is
M1/WR/RD/IORQ/MREQ, active low. No trace realignment is applied; all differences
remain in the counts, and strict mode permits none.
The bench is indexed as slow to keep its GHDL prerequisite out of the ordinary
Verilator-only fast gate; run it explicitly for TV80 changes.

The top instantiates production GHDL T80pa, the actual TV80 wrapper/core, and an
IOWait(0) control. Only a generated wrapper copy under `obj_dir` is renamed and
parameterized to avoid the module-name collision; tracked DUT files are not
mutated by the probe. Each CPU owns separate RAM initialized from the same short
program. Each receives the same reset, INT and WAIT and CEN_p/CEN_n pulses at
phases 0/8 of a 16-clock T-state. Inputs use each CPU's own pins and RAM.

Two initial NOPs initialize production `IntCycleD_n`, which T80pa does not reset.
The first 128 clocks are compared and reported separately, never counted as
transaction coverage. The default gate permits only an IORQ difference there;
any other startup pin mismatch fails. RAM writes are always serviced, independent
of that coverage window. With this Verilator initialization, IORQ spuriously goes
low during the first fetch (ticks 8–31); memory RD has data-mux priority during
that overlap. This is a startup-model observation, not a hardware assertion.

Programs cover separate memory, I/O, IM1 acknowledge and WAIT scenarios. Memory
writes are read back and stored to a second address; IN returns 0x5A and must
reach RAM; each model must use I/O port 0x1234 and OUT data 0x99. All three CPUs must reach HALT before the 4096-clock limit. IRQ also
requires exactly one post-startup acknowledge and a handler fetch per CPU; the
handler halts rather than attempting unsupported TV80 interrupt return. External
WAIT is one common 48-clock pulse triggered by production's read of 0x8000;
checks require both CPUs' reads to lengthen relative to the unstalled scenario.

## Evidence

Base: `4453b760027f575d6c1c147492c53c1a24cd2de7`. Commands above use synthetic
instructions; no firmware, ASIC or motherboard participates.

Before the fix, the focused command
`sim/plus/obj_dir/b23_cpu_diff/b23_cpu_diff_tests --require-memory-parity`
exited 1. Both memory scenarios had 192 post-startup mismatching clocks, **all on
M1**; MREQ/IORQ/RD/WR matched. After the ordinary-fetch-only change, the same
command exited 0. The cross-implementation comparison remains useful because
both instruction sequencing and wrappers are changing independently.

| Scenario/measurement | Production T80 | TV80 after fix | IOWait(0) control |
|---|---:|---:|---:|
| Memory body pin mismatching clocks | reference | 0 | not parity-gated |
| I/O body pin mismatching clocks | reference | 0 | not parity-gated |
| WAIT body pin mismatching clocks | reference | 0 | not parity-gated |
| I/O read window, master clocks | 40 | 40 | 24 |
| I/O write window, master clocks | 40 | 40 | 24 |
| Read of 0x8000, no WAIT / WAIT | 32 / 80 | 32 / 80 | 32 / 80 |
| IRQ IORQ fall / rise, absolute clock | 712 / 736 | 680 / 728 | 680 / 728 |
| IRQ acknowledge window, master clocks | 24 | 48 | 48 |
| IRQ stack write transactions | 2 | 0 | 0 |

All three CPUs execute exactly one tested memory read/write or I/O read/write in
the corresponding scenario. The I/O control preserves independent evidence for
`6b73728`'s automatic-wait repair: its windows shorten by one 16-clock T-state.
The bench asserts equality to production and that the control differs, rather
than copying the 40/24 constants into the test.

IRQ M1 falls at tick 672 in both current CPUs. First body divergence is IORQ at
680. The remaining 209 differing body clocks span IORQ, M1, refresh, stack cycles
and subsequent execution. They are not all attributable to one edge defect.
`tv80_core.v` explicitly jumps to 0x0038 without the two interrupt stack writes;
`t80pa.v` directly shapes IORQ around that reduced sequencer rather than using
the production delayed acknowledge. Repairing those together is outside this
narrow M1 fix. The trace continues without resynchronization through handler
entry and preserves these differences.
